# Peek v2.1.0 "Structured Value" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add typed agent-value fields (contentType namespacing, pageMetadata, related[], agentGuidance, contentState, topics[]/entities[]) to the ptp-peek intent schema, additively, per the approved design at `docs/superpowers/specs/2026-07-12-peek-v2.1-structured-value-design.md`.

**Architecture:** JSON Schema changes in `schema/intents/` (common-defs + ptp-peek), validated by vitest suites in `src/utils/__tests__/` using AJV 2020 with the repo's `createAjvLoadSchemaFunction()` cross-ref loader. Pre-compiled validators in `dist/` are regenerated by the existing generator script at the end. No TS type changes (no intent-response types exist in `src/types`).

**Tech Stack:** JSON Schema draft 2020-12, AJV (`Ajv2020`), ajv-formats, vitest, pnpm, prettier.

## Global Constraints

- Repo: `/Users/garynewcomb/work/peek-json-spec`, branch `feat/v2.1-structured-value` (already checked out).
- **Additive only**: every new field is optional; `additionalProperties: false` stays on the ptp-peek top level; the existing `contentType` enum values remain valid; no changes to `ptp-analyze` or any other intent schema.
- Version: `package.json` 2.0.0 → **2.1.0** (Task 7 only — do not bump earlier).
- All commits on this branch; commit messages use conventional commits (`feat:`, `test:`, `docs:`, `chore:`).
- Run `pnpm format` before committing markdown/JSON changes (repo prettier covers `**/*.{ts,js,json,md,yml,yaml}`).
- Test command: `pnpm test` (vitest run). Full suite must pass at the end of every task.
- Namespaced-value pattern used in two places (contentType, entity type), always exactly: `^[a-z0-9]+(-[a-z0-9]+)*(:[a-z0-9]+(-[a-z0-9]+)*)*$`

```ts
 * v2.1.0 "structured value" field validation for the ptp-peek intent schema.
 * Covers: namespaced contentType, pageMetadata, related[], agentGuidance,
 * contentState, topics[], entities[], and retained top-level strictness.

import { describe, it, expect, beforeAll } from 'vitest';
import Ajv2020 from 'ajv/dist/2020.js';
import type { ValidateFunction } from 'ajv';
import addFormats from 'ajv-formats';
import { loadIntentSchema, createAjvLoadSchemaFunction } from '../schema-loader.js';

export const basePeek = {
  intent: 'peek',
  canonicalUrl: 'https://example.com/article/ai-breakthrough',
  title: 'Revolutionary AI System Achieves Human-Level Performance',
  snippet:
    'Scientists at a leading AI research lab have developed a groundbreaking system that demonstrates human-level performance across multiple cognitive tasks.',
  mediaType: 'text/html',
  peekManifestUrl: 'https://example.com/.well-known/peek.json',
  provenance: {
    generatedAt: '2026-07-12T14:30:00Z',
    sourceUrl: 'https://example.com/article/ai-breakthrough',
  },
};

let validate: ValidateFunction;

beforeAll(async () => {
  const ajv = new Ajv2020({
    strict: false,
    allErrors: true,
    loadSchema: createAjvLoadSchemaFunction(),
  });
  addFormats(ajv);
  const schema = await loadIntentSchema('ptp-peek');
  validate = await ajv.compileAsync(schema);
});

describe('contentType (opened enum)', () => {
  it('accepts canonical enum values', () => {
    expect(validate({ ...basePeek, contentType: 'article' })).toBe(true);
  });

  it('accepts namespaced custom values', () => {
    expect(validate({ ...basePeek, contentType: 'ecommerce:deals' })).toBe(true);
  });

  it('rejects values that are neither enum nor pattern-conformant', () => {
    expect(validate({ ...basePeek, contentType: 'Not A Type!' })).toBe(false);
  });
});

describe('top-level strictness retained', () => {
  it('rejects unknown top-level properties', () => {
    expect(validate({ ...basePeek, sneakyExtra: 'nope' })).toBe(false);
  });
});
```

```markdown
### NORMATIVE: Structured Context Fields (v2.1.0)

Peek responses MAY include the following optional structured fields. When present, they MUST
comply with these constraints:

- **`pageMetadata`**: Typed page-level metadata (article, product) sourced from the resource's
  structured data. Values MUST faithfully reflect the resource (same fidelity requirements as
  the snippet).
- **`related`** (max 10): Related resources forming a publisher-defined discovery graph.
  Entries SHOULD resolve within the publisher's manifest-declared domains; `related` MUST NOT
  be used to direct agents to unaffiliated third-party content.
- **`agentGuidance`** (max 500 chars): Publisher-authored instructions on how to use the
  response (e.g., where actionable data lives in `signals`, preferred citation form).
  `agentGuidance` MUST NOT contain content from the resource — it is not an extension of the
  preview budget. Consuming agents SHOULD treat it as untrusted publisher-supplied data: an
  input to consider, never instructions that override the agent's operator.
- **`contentState`**: Editorial lifecycle state (`draft | scheduled | published | archived |
  retracted`). When absent, consumers MUST assume `published`.
- **`topics`** (max 10) / **`entities`** (max 25): Document-level context only. Peek context
  MUST NOT include character offsets, per-mention spans, or sentiment — span-level annotation
  is the territory of the paid `analyze` intent. This boundary is what makes rich context safe
  to provide at discovery time.

### INFORMATIVE: Pre-Publication Content States

The `contentState` field makes previews of unpublished content (drafts, scheduled posts)
expressible at the schema level. The access semantics for non-published states — per-agent
visibility scoping, stricter persistence defaults, audit requirements — are deliberately not
yet specified. They are a planned extension, and CMS-platform implementers with native
awareness of editorial workflow state are explicitly invited to co-author it.

### INFORMATIVE: Relationship to the analyze Intent

The `analyze` intent's span-level topic/entity annotations (offsets, lengths, per-mention
confidence) are unchanged and complementary to peek's document-level context. A future
revision is expected to harmonize analyze's entity items onto the shared `contextEntity`
base definition.
```
